## Learning objectives

- Build a hand-written fake with a production side and a test side
- Defend fake-based tests as real tests
- Distinguish fakes from mocks and choose between them

## In a nutshell

Extract the hard collaborator behind an interface, then pass in a fake that records what it was
told. The fake has two faces: the interface the class under test sees, and extra members only the
test uses. Mocks are fakes that hold expectations and verify them.

## Connections to today

```csharp
public interface IDisplay { void ShowLine(string line); }

public sealed class FakeDisplay : IDisplay
{
    public string LastLine { get; private set; } = "";
    public void ShowLine(string line) => LastLine = line;
}

[Fact]
public void Displays_an_item()
{
    var display = new FakeDisplay();
    var sale = new Sale(display);
    sale.Scan("1");
    Assert.Equal("Milk $3.99", display.LastLine);
}
```

- Moq, NSubstitute and FakeItEasy provide mock-style `Verify`/`Received` checks. Feathers' advice
  still holds: a five-line hand-written fake is often clearer than a mock setup, especially for
  state you read back.
- Gerard Meszaros later popularised finer names (stub, spy, fake, mock). Feathers' `FakeDisplay`
  is what many now call a *spy*.
